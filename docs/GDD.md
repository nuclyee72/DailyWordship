## 1. 한 줄

> 초성만 보이는 8×8 바다에 숨은 함선 6척의 **이름**을, 추측 30번 안에 모두 밝혀라.

배틀십(어디에 있나) + 워들(무슨 단어인가). 같은 날엔 모두 같은 판을 푼다 — DailySudoku·DailyTrilateral과 같은 계열.

## 2. 보드

| 항목 | 값 |
|---|---|
| 크기 | 8×8. 열 `a`~`h`(왼→오), 행 `1`~`8`(위→아래) |
| 칸 | 모든 칸의 **초성이 처음부터 공개**. 음절은 숨겨져 있다 |
| 함선 칸 | 초성 = 함명 음절의 초성 |
| 빈 칸 | 출제 풀 음절의 초성 빈도로 뽑은 무작위 초성 (ㅇ 15% · ㅅ 14% · ㄱ 13% · ㅈ 12% …) |

## 3. 함대

| 길이 | 수 | 함명 |
|---|---|---|
| 4칸 | 1 | 4글자 명사 |
| 3칸 | 3 | 3글자 명사 |
| 2칸 | 2 | 2글자 명사 |

총 6척 17칸. **방향 4종 — 가로(→) · 세로(↓) · 대각(↘ ↗)**, 읽는 방향은 이 네 가지로 고정.
겹침만 금지하고 **접촉은 허용**(대각 함선끼리 X자로 교차해도 칸을 공유하지 않으면 된다). 네 함명은 서로 다르다.

## 4. 추측 — 유일한 행동

1. 판에서 직선 **2~4칸**을 드래그한다(4방향. 거꾸로 끌어도 고정 방향으로 읽는다). 두 칸을 차례로 눌러도 된다.
2. 박스의 초성과 **정확히** 맞는 명사를 입력한다(경음 대체 불가 — `ㄲ` 칸에 `가` 불가).
3. 사전에 없는 단어 · 초성 불일치 · 같은 박스에 같은 단어 재추측은 **거절되고 횟수를 쓰지 않는다**.

### 칸별 결과 (박스의 칸마다 독립 판정)

| 결과 | 조건 | 표시 |
|---|---|---|
| 빈 바다 | 함선 없음 | 어둡게 |
| 명중 | 함선 있음, 음절 틀림 | 주황 |
| 공개 | 함선 있음, 음절 맞음 | 노랑 + 음절 |
| 힌트 | 추측 박스가 **이전 추측에서 주황이 된 칸**을 지나감 — 단어가 틀려도. 그런 칸이 여럿이면 박스에서 **가장 앞(번호가 낮은) 칸 하나만**. 박스 밖 칸은 열리지 않는다 | 그 칸 글자 노랑 공개 |
| 완성 | 함선 자리(칸·방향 그대로)에 **함선 이름을 정확히 입력** — 글자가 전부 노랑이어도 이름 입력은 따로 필요 | 그 함선 칸 전부 초록 + 캡슐 외곽선 |

### 승패

- 6척 모두 완성 → **성공**
- **추측 30번** 소진 → 실패, '정답 보기'로 못 찾은 함명 확인

## 5. 생성

`src/game/generator.js` — 시드가 같으면 결과도 같다. 데일리 시드 `daily:YYYY-MM-DD`, 자유 연습은 무작위.

1. 함선 배치 (4방향 무작위, 겹침만 금지)
2. 함명 — 출제 풀에서 길이별 무작위, 서로 다르게
3. 빈 칸 초성 — 빈도 가중 추출, 드문 된소리(ㄲㄸㅃㅆㅉ) 연속 금지
4. **미끼 검사** — 출제어 초성열과 맞는데 함선이 아닌 박스가 길이별 최소 개수(2칸 150 · 3칸 40 · 4칸 4) 이상. 4칸은 자연 발생이 드물어(판당 중앙값 8개) 모자라면 빈 칸에 미끼 초성열을 심는다

### 5.2 고유명사

출제 풀에서는 뺀다(`curated/blocklist.txt` — 지명·국가·궁궐·산·종교 대상 등). 추측 사전에서는 막지 않는다 —
추측 사전의 역할은 "아무 음절이나 넣어 떠보기"를 막는 것뿐이라 넉넉한 편이 낫다.

### 5.3 밸런스 측정 (`scripts/simulate.mjs`)

봇 = 출제 풀 단어를 전부 알고, 보드에서 출제어 초성열이 보이는 박스를 긴 것부터 찍으며, 명중·공개 칸이 생기면 그 칸을 지나는 박스를 알려진 음절에 맞는 단어로 메운다. 한도 없이 두게 해서 몇 번 만에 푸는지 본다.

| 규칙 | 20회 안 성공 | 25회 | 30회 | 40회 |
|---|---|---|---|---|
| 음절만 공개 · 6척(4·3·3·3·2·2) | 0% | 0% | 0% | 0% |
| + 명중 표시 · 6척 | 10% | 35% | 59% | 91% |
| 음절만 공개 · 4척(4·3·3·2) | 1% | 1% | 6% | 13% |
| + 명중 표시 · 4척(4·3·3·2) | 64% | 89% | 96% | 100% |

| 명중 칸 재추측 시 이름 공개 규칙 | 15회 안 성공 | 20회 | 중앙 |
|---|---|---|---|
| 4척(4·3·3·2) · v1.1 | 85% | 99% | 12 |
| 6척, 재추측 시 가장 앞 칸 함선 이름 전부 공개 → 완성 · v1.2 | 63% | 91% | 15 |
| **6척, 재추측 시 가장 앞 주황 칸 글자 하나만 힌트 · 완성은 이름 입력 · 채택 (v1.3)** | 5% | **64%** | 19 |

v1.3 채택안: 300판 기준 최소 12 · 중앙 19 · 75% 22 · 최대 31회, 25회 안 94%. v1.4에서 한도를 30으로 올렸다(봇 기준 30회 안 100%) — 사람은 어휘가 봇보다 좁아 여유를 더 줬다.
v1.2는 박스 밖 칸까지 열리고 바로 초록이 되어 "힌트"가 아니라 정답 공개가 돼 버렸다 — v1.3에서 선택한 칸 안의 글자 하나로 좁혔다.
함선마다 이름을 한 번 입력해야 완성되므로 최소 6회는 '이름 입력'에 쓰인다.

**v1.1 — 글자 맞히기가 너무 어렵다는 피드백.** 칸 찾기(명중)는 괜찮았지만, 초성만 보고 정확한 음절을 맞히기가 지나치게 어려웠다.
그래서 "함선을 찾았다면 한 번 더 건드리면 이름이 드러난다"로 바꿨다. 게임의 중심이 **어디 있나(배틀십)** 쪽으로 옮겨졌고,
단어 실력은 '한 번에 맞혀서 추측 1회를 아끼는 것'으로 보상받는다.

**2칸 함선이 난이도를 좌우한다.** 무작위 2초성 박스는 거의 전부(판당 약 200/210개) 상용어와 초성이 맞아 초성만으로는 위치를 전혀 좁힐 수 없다. 그래서 '음절이 맞아야만 정보' 규칙으로는 풀 수 없었고, 명중 표시를 넣고 2칸함을 한 척으로 줄였다.

봇은 어휘를 완벽히 알지만 추론은 단순하다(명중 칸 사이의 방향을 따지지 않음). 사람은 그 반대라 실제 성공률은 달라질 수 있다 — 실사용 통계를 보고 한도(30)와 미끼 기준을 다시 조정한다.

## 9. 사자성어 모드

| 항목 | 스탠다드 | 사자성어 |
|---|---|---|
| 함대 | 4·3·3·3·2·2 (6척) | **4·4·4·4·4 (5척)** |
| 함명 | 상용 명사 2~4글자 | **사자성어만** (`src/data/answers-idiom.txt`, 416개) |

| 데일리 파일 | `daily/<date>.json` | `daily/idiom-<date>.json` (시드 `daily-idiom:<date>`) |
| 저장 키 | `wordship:progress:<date>` · `wordship:stats` | `wordship:progress:idiom:<date>` · `wordship:stats:idiom` |

규칙(칸별 결과·힌트·완성)은 스탠다드와 같다. 메인 화면 두 번째 카드, 지난 퍼즐·통계의 모드 전환, 자유 연습의 모드 선택으로 들어간다. 모드 정의는 `src/game/modes.js`.

**출제 풀** — 직접 고른 널리 아는 사자성어 407개(`curated/idioms-extra.txt`)에 영어 위키낱말사전 'Korean four-character idioms' 분류를 받아 합친다.
위키낱말사전 쪽은 직접 목록이나 표준국어대사전 명사 목록에도 있는 것만 쓴다(`교하질쉬` 같은 낯선 성어 배제).
표준국어대사전 명사 목록은 `새옹지마`·`일석이조`처럼 붙임표가 든 표제어가 빠져 있어 검증 기준으로 쓰지 않았다.

**미끼** — 2·3칸 함선이 없으니 4칸 미끼만 본다. 자연 발생 판당 중앙값 7개, 최소 5개(모자라면 심는다).

**밸런스 (봇 300판)** — 중앙 7회 · 최대 11회로 스탠다드(중앙 19회)보다 훨씬 쉽다.
사자성어 초성열은 거의 유일해서 초성만 보고 위치를 찍을 수 있기 때문. 봇은 416개를 전부 아는 셈이라 사람 체감과는 다르다 — 실사용을 보고 한도·미끼를 조정한다.

### 10.1 기믹 19종

| 분류 | id | 이름 | 규칙 |
|---|---|---|---|
| 판 | `wide` | 🌊 넓은 바다 | 판 **10×10** |
| 판 | `narrow` | 🏝️ 좁은 바다 | 판 **7×7** (함대는 그대로라 빽빽함) |
| 판 | `donut` | 🍩 도넛 바다 | 판 **12×12**, 가운데 **4×4가 뚫림**(128칸). 구멍에는 함선이 없고 박스가 지나갈 수 없다 |
| 함대 | `extra4` · `extra3` · `extra2` | 🚢 ⛴️ 🚤 증원 | 4·3·2칸 함선 +1척 (증원끼리 겹치면 8척) |
| 정보 | `fog` | 🔒 잠긴 칸 | 판 칸의 1/6이 **초성까지 가려진다**(0단계 정보 — 초성이 1단계, 음절이 2단계). 그 자리엔 **아무 초성의 글자나** 넣을 수 있고, 추측에 한 번 포함되면 초성이 드러난다 |
| 정보 | `cross` | ❌ 대각선 잠김 | 판의 **두 대각선(X자)** 칸이 잠긴 칸. `fog`와 겹치면 `fog`는 대각선 밖에서 뽑는다 |
| 비용 | `costly` | 3️⃣ 길이 3 선호 | 2·4글자로 추측해 **함선을 완성하지 못하면 −2**. **함선을 완성하면(길이 무관) +1** 돌려받는다 |
| 비용 | `checkpoint` | 🚩 관문 | **10 · 20 · 30번째 추측**은 함선을 완성해야 한다. 못 하면 그때마다 **−5** (번째는 추측 개수 기준, 벌점과 무관) |
| 비용 | `lowStart` | ⏳ 보급 부족 | **시작부터 3번 쓴 상태** — 한도 35면 32번으로 시작 |
| 제한 | `alternate` | 🔀 길이 바꾸기 | 직전 추측과 **같은 길이** 금지 |
| 제한 | `turn` | 🧭 방향 바꾸기 | 직전 추측과 **같은 방향**(→ ↓ ↘ ↗) 금지 |
| 제한 | `apart` | ↔️ 거리 두기 | 직전 추측 칸과 **둘레 8칸** 금지 |
| 제한 | `lineStart` | ⏮️ 첫 칸 십자 | 직전 추측 **첫 칸의 가로줄·세로줄 전체** 금지 |
| 제한 | `lineEnd` | ⏭️ 끝 칸 십자 | 직전 추측 **끝 칸의 가로줄·세로줄 전체** 금지 |
| 제한 | `noOrange` | 🟧 연속 주황 금지 | 주황 칸을 포함한 추측을 **두 번 연달아** 할 수 없다 — 직전 추측이 (그때) 주황이던 칸을 지나갔으면, 이번엔 지금 주황인 칸을 못 쓴다 |
| 제한 | `noMiss` | 🚫 회색 칸 금지 | 빈 바다로 확인된 **회색 칸** 금지 |
| 제한 | `gray3` | 🔁 회색 칸 필수 | **3 · 6 · 9 …번째 추측**은 회색 칸을 하나 이상 포함해야 한다. 판에 회색 칸이 아직 없으면 면제 |

- '제한' 위반은 추측을 **거절하고 횟수를 쓰지 않는다**. 박스를 고르는 순간 바로 안내하고, 못 쓰는 칸은 판에 빗금으로 표시한다.
- 그날의 기믹은 **화면 왼쪽 끝 책갈피**로 보여 준다 — 데일리 스도쿠 익스텐디드의 요소 책갈피와 같은 방식(손잡이를 누르면 이름·설명이 밀려 나옴).
  배지에는 지금 상태(이번엔 4글자 ✕ · 10번째 격침 필수 · 잠긴 칸 16 …). 좁은 화면에선 손잡이 폭만큼 판을 오른쪽으로 비운다.
- 제약이 겹쳐 **고를 수 있는 박스가 하나도 없으면** 그 한 번은 직전 추측에 따른 제약(길이·방향·빗금·회색 필수)을 모두 푼다 — 데일리가 막혀 못 푸는 일이 없게. 함대 줄 아래에 '제약 해제'가 뜬다.
- 판이 8×8이 아니면 미끼 최소 개수(§5)를 (구멍을 안 지나는) 박스 수에 비례해 맞춘다 — 7×7에서 8×8 기준(2칸 150)은 불가능하다.
- 판이 끝나면 잠긴 칸은 모두 걷히고 빗금도 사라진다.
- 공유 문구와 결과 창에 그날의 기믹 줄이 붙는다. 추측 수는 벌점·보상 반영. 기록 목록엔 −2 · +1 · 🚩−5 · 🚩(관문 통과) 표시.
- 모든 모드 공통: 함선을 완성한 추측은 기록 목록에 초록 줄로 표시한다.

### 10.2 그날의 조합

19종의 2종 조합 171개에서 **함께 못 나오는 짝 4개**(판 크기끼리 3개, 회색 칸 금지 ↔ 회색 칸 필수)를 빼 **167개**.
2026-09-23부터 **167일에 한 바퀴** — 바퀴마다 조합을 시드(`extended-gimmicks:<바퀴>`)로 섞어 하루 하나씩 쓴다.
같은 조합이 이틀 연속 나오지 않게, 바퀴가 바뀌는 날 전 바퀴 마지막 날과 같으면 둘째 날 것과 맞바꾼다. 자유 연습은 아무 조합이나.
기믹 수가 바뀌면 순서도 통째로 바뀐다 — 이미 만든 날짜의 파일은 그대로 두고(그 파일에 기믹이 적혀 있다) 새 날짜부터 새 순서를 쓴다(09-23~28은 13·18종 시절 순서).

## 7. 개발

```sh
npm test                 # 규칙·생성기 단위 테스트
npm run simulate         # 밸런스 봇 (node scripts/simulate.mjs [판 수] [standard|extended|idiom] [시드] [기믹=costly+wide])
npm run generate-daily   # 오늘+3일 퍼즐 생성 (세 모드 모두)
npm run dev              # 로컬 서버 http://localhost:8420/
npm run test-e2e         # Playwright — 랜딩 → 플레이 → 결과 → 새로고침 복원
npm run build-word-data  # 단어 데이터 다시 만들기
```

콘솔 `__solve()` — 남은 함선 이름을 그대로 추측해 판을 끝낸다(테스트용).
콘솔 `__freePlay('extended', ['wide', 'fog'])` — 기믹을 골라 익스텐디드 자유 연습(테스트용).

## 8. 남은 판단거리

- 추측 한도 30이 사람에게 적당한가 — 실사용 분포를 보고 결정
- 익스텐디드 조합별 난이도 차이(봇 기준 35회 안 41~100%) — 도넛 바다 짝(특히 회색 칸 필수·관문)을 막거나 도넛 날 한도를 늘릴지 실사용을 보고 결정
- 추측 사전에 빠진 일상 합성어 제보 처리 흐름
