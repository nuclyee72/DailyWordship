# 데일리 워십 — 기획서 v1.0 (솔로 데일리 퍼즐)

> 이전 버전(실시간 2인 대전, 행동 4종, 8×20 보드)은 [archive/GDD-v0.9-multiplayer.md](archive/GDD-v0.9-multiplayer.md)에 보관.
> v1.3: 함대 6척(4·3·3·3·2·2), 추측 20. 주황 칸 재추측 → 그 칸 글자 하나만 노랑 힌트. 완성(초록)은 함선 자리에 이름을 정확히 입력할 때만. 공유는 함선별 칸 그림 (§3, §4, §5.3, §6).
> v1.0에서 멀티플레이·AP·쿨타임·이동·탐지·포격을 모두 없애고, **옛 '식별'(함명 추측) 하나만 남긴 하루 한 판 퍼즐**이 되었다.

## 1. 한 줄

> 초성만 보이는 8×8 바다에 숨은 함선 6척의 **이름**을, 추측 20번 안에 모두 밝혀라.

배틀십(어디에 있나) + 워들(무슨 단어인가). 같은 날엔 모두 같은 판을 푼다 — DailySudoku·DailyTrilateral과 같은 계열.

## 2. 보드

| 항목 | 값 |
|---|---|
| 크기 | 8×8. 열 `a`~`h`(왼→오), 행 `1`~`8`(위→아래) |
| 칸 | 모든 칸의 **초성이 처음부터 공개**. 음절은 숨겨져 있다 |
| 함선 칸 | 초성 = 함명 음절의 초성 |
| 빈 칸 | 출제 풀 음절의 초성 빈도로 뽑은 무작위 초성 (ㅇ 15% · ㅅ 14% · ㄱ 13% · ㅈ 12% …) |

## 3. 함대

| 길이 | 수 | 함명 |
|---|---|---|
| 4칸 | 1 | 4글자 명사 |
| 3칸 | 3 | 3글자 명사 |
| 2칸 | 2 | 2글자 명사 |

총 6척 17칸. **방향 4종 — 가로(→) · 세로(↓) · 대각(↘ ↗)**, 읽는 방향은 이 네 가지로 고정.
겹침만 금지하고 **접촉은 허용**(대각 함선끼리 X자로 교차해도 칸을 공유하지 않으면 된다). 네 함명은 서로 다르다.

## 4. 추측 — 유일한 행동

1. 판에서 직선 **2~4칸**을 드래그한다(4방향. 거꾸로 끌어도 고정 방향으로 읽는다). 두 칸을 차례로 눌러도 된다.
2. 박스의 초성과 **정확히** 맞는 명사를 입력한다(경음 대체 불가 — `ㄲ` 칸에 `가` 불가).
3. 사전에 없는 단어 · 초성 불일치 · 같은 박스에 같은 단어 재추측은 **거절되고 횟수를 쓰지 않는다**.

### 칸별 결과 (박스의 칸마다 독립 판정)

| 결과 | 조건 | 표시 |
|---|---|---|
| 빈 바다 | 함선 없음 | 어둡게 |
| 명중 | 함선 있음, 음절 틀림 | 주황 |
| 공개 | 함선 있음, 음절 맞음 | 노랑 + 음절 |
| 힌트 | 추측 박스가 **이전 추측에서 주황이 된 칸**을 지나감 — 단어가 틀려도. 그런 칸이 여럿이면 박스에서 **가장 앞(번호가 낮은) 칸 하나만**. 박스 밖 칸은 열리지 않는다 | 그 칸 글자 노랑 공개 |
| 완성 | 함선 자리(칸·방향 그대로)에 **함선 이름을 정확히 입력** — 글자가 전부 노랑이어도 이름 입력은 따로 필요 | 그 함선 칸 전부 초록 + 캡슐 외곽선 |

### 승패

- 6척 모두 완성 → **성공**
- **추측 20번** 소진 → 실패, '정답 보기'로 못 찾은 함명 확인

## 5. 생성

`src/game/generator.js` — 시드가 같으면 결과도 같다. 데일리 시드 `daily:YYYY-MM-DD`, 자유 연습은 무작위.

1. 함선 배치 (4방향 무작위, 겹침만 금지)
2. 함명 — 출제 풀에서 길이별 무작위, 서로 다르게
3. 빈 칸 초성 — 빈도 가중 추출, 드문 된소리(ㄲㄸㅃㅆㅉ) 연속 금지
4. **미끼 검사** — 출제어 초성열과 맞는데 함선이 아닌 박스가 길이별 최소 개수(2칸 150 · 3칸 40 · 4칸 4) 이상. 4칸은 자연 발생이 드물어(판당 중앙값 8개) 모자라면 빈 칸에 미끼 초성열을 심는다

### 5.1 단어 데이터

[src/data/README.md](../src/data/README.md) 참고. 출제 풀 2글자 2,145 · 3글자 737 · 4글자 739 / 추측 사전 75,712 · 108,007 · 10,691.
4글자 출제 풀은 상용 목록(124개)을 표준국어대사전 4글자 8,634개 전수 검토와 일상 복합어 직접 추가로 보강했다.

### 5.2 고유명사

출제 풀에서는 뺀다(`curated/blocklist.txt` — 지명·국가·궁궐·산·종교 대상 등). 추측 사전에서는 막지 않는다 —
추측 사전의 역할은 "아무 음절이나 넣어 떠보기"를 막는 것뿐이라 넉넉한 편이 낫다.

### 5.3 밸런스 측정 (`scripts/simulate.mjs`)

봇 = 출제 풀 단어를 전부 알고, 보드에서 출제어 초성열이 보이는 박스를 긴 것부터 찍으며, 명중·공개 칸이 생기면 그 칸을 지나는 박스를 알려진 음절에 맞는 단어로 메운다. 한도 없이 두게 해서 몇 번 만에 푸는지 본다.

| 규칙 | 20회 안 성공 | 25회 | 30회 | 40회 |
|---|---|---|---|---|
| 음절만 공개 · 6척(4·3·3·3·2·2) | 0% | 0% | 0% | 0% |
| + 명중 표시 · 6척 | 10% | 35% | 59% | 91% |
| 음절만 공개 · 4척(4·3·3·2) | 1% | 1% | 6% | 13% |
| + 명중 표시 · 4척(4·3·3·2) | 64% | 89% | 96% | 100% |

| 명중 칸 재추측 시 이름 공개 규칙 | 15회 안 성공 | 20회 | 중앙 |
|---|---|---|---|
| 4척(4·3·3·2) · v1.1 | 85% | 99% | 12 |
| 6척, 재추측 시 가장 앞 칸 함선 이름 전부 공개 → 완성 · v1.2 | 63% | 91% | 15 |
| **6척, 재추측 시 가장 앞 주황 칸 글자 하나만 힌트 · 완성은 이름 입력 · 채택 (v1.3)** | 5% | **64%** | 19 |

v1.3 채택안: 300판 기준 최소 12 · 중앙 19 · 75% 22 · 최대 31회, 25회 안 94%.
v1.2는 박스 밖 칸까지 열리고 바로 초록이 되어 "힌트"가 아니라 정답 공개가 돼 버렸다 — v1.3에서 선택한 칸 안의 글자 하나로 좁혔다.
함선마다 이름을 한 번 입력해야 완성되므로 최소 6회는 '이름 입력'에 쓰인다.

**v1.1 — 글자 맞히기가 너무 어렵다는 피드백.** 칸 찾기(명중)는 괜찮았지만, 초성만 보고 정확한 음절을 맞히기가 지나치게 어려웠다.
그래서 "함선을 찾았다면 한 번 더 건드리면 이름이 드러난다"로 바꿨다. 게임의 중심이 **어디 있나(배틀십)** 쪽으로 옮겨졌고,
단어 실력은 '한 번에 맞혀서 추측 1회를 아끼는 것'으로 보상받는다.

**2칸 함선이 난이도를 좌우한다.** 무작위 2초성 박스는 거의 전부(판당 약 200/210개) 상용어와 초성이 맞아 초성만으로는 위치를 전혀 좁힐 수 없다. 그래서 '음절이 맞아야만 정보' 규칙으로는 풀 수 없었고, 명중 표시를 넣고 2칸함을 한 척으로 줄였다.

봇은 어휘를 완벽히 알지만 추론은 단순하다(명중 칸 사이의 방향을 따지지 않음). 사람은 그 반대라 실제 성공률은 달라질 수 있다 — 실사용 통계를 보고 한도(20)와 미끼 기준을 다시 조정한다.

## 6. 데일리

| 항목 | 내용 |
|---|---|
| 경계 | KST 06:00 (`src/daily/dateUtil.js`, 형제 게임과 동일) |
| 생성 | GitHub Actions 크론 05:00 KST → `daily/<date>.json` (오늘+3일 버퍼, 멱등) |
| 진행 저장 | `wordship:progress:<date>` — **추측 목록만** 저장하고 화면은 매번 다시 계산 |
| 통계 | 게임 수 · 승률 · 연승 · 최고 연승 · 사용 추측 수 분포(5개 단위) · 달력 |
| 지난 퍼즐 | 2026-09-23부터. 연습용이라 통계에 안 들어간다 |
| 자유 연습 | 브라우저에서 즉석 생성. 기록 안 함 |
| 공유 | 함선별 칸 그림 — 완성한 함선은 🟩, 아니면 칸별로 🟨 글자 공개 · 🟧 명중 · ⬜ 못 찾음. 긴 함선과 짧은 함선을 한 줄에 짝지음 (위치는 드러나지 않음) |

## 7. 개발

```sh
npm test                 # 규칙·생성기 단위 테스트
npm run simulate         # 밸런스 봇 (node scripts/simulate.mjs [판 수] [시드] [함대])
npm run generate-daily   # 오늘+3일 퍼즐 생성
npm run dev              # 로컬 서버 http://localhost:8420/
npm run test-e2e         # Playwright — 랜딩 → 플레이 → 결과 → 새로고침 복원
npm run build-word-data  # 단어 데이터 다시 만들기
```

콘솔 `__solve()` — 남은 함선 이름을 그대로 추측해 판을 끝낸다(테스트용).

## 8. 남은 판단거리
