# WordShip 행동 레퍼런스

> **조작 방향 [v0.8]** — **행동 버튼을 없앴다.** 무슨 행동인지는 *어디서 드래그를 시작했는가*가 정한다.
> 보드에 남은 버튼은 「포격」 하나뿐이고, 그것도 목표를 찍은 뒤 누르는 확인 버튼이다.

4개 행동의 **조작 흐름 · 전제 조건 · 효과**를 전부 적는다.
기획 의도는 [GDD.md](GDD.md), 구현은 `prototype/src/game.js`.

---

## 0. 공통 규칙

### 0.1 거리는 유클리드(직선 거리) **[v0.6]**

```js
dist(A, B) = √((A.x − B.x)² + (A.y − B.y)²)
```

- 대각선은 √2 ≈ **1.414**. 직선 1칸보다 멀다.
- **함선과 칸의 거리 = 함선이 점유한 타일 중 가장 가까운 것까지의 거리.** 중심이나 머리가 아니다.
- 범위 판정은 제곱끼리 비교해 부동소수점 오차를 피한다 (`dx² + dy² ≤ r²`).

이 때문에 사거리 범위는 **사각형이 아니라 원형**이다. 대각 구석이 잘린다.

```
3칸 함선 포격(r=3) 실제 도달 칸 수

   체비쇼프(구)  9×7 사각형 = 63칸
   유클리드(신)  원형        = 43칸      ← 32% 감소
```

| 범위 | 도달 칸 수 (보드 중앙 기준) | 보드 대비 |
|---|---|---|
| 3칸함 포격 r=3 | 42칸 | 26% |
| 4칸함 포격 r=5 | 80칸 | 50% |
| 식별 r=7 | 110칸 | 69% |
| 이동 인접 r=1.5 | 15칸 (8방향 유지) | 9% |

> **[v0.9]** 보드가 250 → 160칸으로 줄면서 **같은 사거리가 상대적으로 넓어졌다.**
> 식별 r=7 은 54% → 69%, 4칸함 포격 r=5 는 38% → 50%. 사거리 상수는 건드리지 않았으므로
> 밸런스 단계의 관측 대상이다 (GDD §11).

> **이동 인접만 1.5인 이유** — "1칸 이내"는 사거리가 아니라 *맞닿음*이다. √2 < 1.5 이므로 **대각선도 인접으로 인정**되어 기존 8방향 그대로다. 정확히 1.0으로 두면 상하좌우 4방향만 남아 이동이 크게 제약된다. `BALANCE.move.adjacency` 로 바꿀 수 있다.

### 0.1b 보드 규격 **[v0.9 축소]**

| 항목 | v0.8 | **v0.9** |
|---|---|---|
| 크기 | 10 × 25 = 250칸 | **8 × 20 = 160칸** |
| 가로 표기 | `a`~`j` | **`a`~`h`** |
| 배치 구역 | 10 × 10 | **8 × 8** |
| 중립 해역 | 5행 (`y 10~14`) | **4행 (`y 8~11`)** |
| 상륙 목표 | 25행 | **20행** |
| 진영 깊이 | 24칸 | **19칸** |

```
        P2 배치 구역 8×8      y 12~19
        ─────────────────
        중립 해역   8×4       y  8~11
        ─────────────────
        P1 배치 구역 8×8      y  0~ 7
```

함대도 같이 줄었다 (§0.3b). 배치 밀도는 **16/64 = 25%** 로 구 27/100 = 27% 와 거의 같다.

### 0.2 모든 행동이 먼저 통과해야 하는 관문

순서대로 검사하고, 걸리는 즉시 거부한다. **거부되면 AP도 쿨타임도 소모되지 않는다.**

| # | 검사 | 실패 메시지 |
|---|---|---|
| 1 | 전투 페이즈인가 | `전투 중이 아님` |
| 2 | AP가 비용 이상인가 | `AP 부족 (n 보유 / m 필요)` |
| 3 | 그 함선이 내 것이고 살아 있는가 | `자기 함선이 아님` / `침몰한 함선` |
| 4 | 그 함선의 쿨타임이 끝났는가 | `쿨타임 n초 남음` |

AP는 **진영 공유 자원**(2.5초당 1, 최대 10), 쿨타임은 **함선 개별**이다. 둘 중 하나만 막혀도 행동할 수 없다.

### 0.3 비용표

| 행동 | AP | 쿨타임 | 사거리 |
|---|---|---|---|
| 이동 | **3** | 함선 길이 × 3초 (3칸 9s / 4칸 12s) | 인접 1.5 |
| 탐지 | **2** | 5초 | 4방향 쐐기 13칸 (거리 무관) |
| 식별 | 2 | 8초 | 7 |
| 포격 | 1 | 6초 | 3칸함 3 / 4칸함 5 |

> **[v0.8 변경]** 탐지가 1 → **2 AP**. 한 번에 여는 칸이 5칸에서 13칸으로 2.6배 늘었기 때문이다 (§2).
> 이로써 1 AP 행동은 포격 하나만 남았다.

### 0.3b 함대 **[v0.9 축소]**

| 길이 | 수량 | HP | 포격 사거리 | 함명 길이 | 이동 쿨 |
|---|---|---|---|---|---|
| 4 | **1척** | 10 | 5 | 4글자 | 12초 |
| 3 | **4척** | 6 | 3 | 3글자 | 9초 |

**5척 / 16칸 / 총 HP 34** (구 8척 / 27칸 / HP 60).

4칸함이 **한 척뿐**이라는 것이 이 변경의 핵심이다. 사거리 5짜리 화력함이 하나라서, 그 배를 어디에 두느냐가 곧 전선의 위치가 된다. 나머지 4척은 전부 3칸 — **돌파와 정찰이 함대의 기본 성격**이 된다.

> 보드가 좁아진 만큼 함대도 줄여 **밀도를 유지**했다. 25% 대 27%.
> 다만 **총 HP 가 60 → 34 로 43% 줄어** 전멸 승리가 상대적으로 가까워졌다. 관측 대상.

### 0.4 공통 조작 **[v0.8 — 모드 없음]**

행동 버튼이 없다. **누른 칸 하나가 행동을 결정한다.**
상태는 딱 둘뿐이다 — 함선을 골랐는가, 안 골랐는가.

#### 함선 선택됨

고르는 순간 **초록 테두리**(이동 시작 칸)와 **붉은 칠**(포격 사거리)이 같이 뜬다.

| 조작 | 행동 |
|---|---|
| **함선 타일**에서 드래그 | **탐지** — 끈 방향(상하좌우)으로 쐐기 |
| **초록 테두리**에서 드래그 | **이동** — 놓으면 단어 입력 |
| **붉은 칠 안**의 칸 클릭 → 「포격」 | **포격** — 같은 칸을 한 번 더 눌러도 발사 |
| **사거리 밖** 클릭 | **선택 취소** |
| 다른 아군 함선 클릭 | 그 함선으로 선택 이동 |

#### 함선 선택 없음

| 조작 | 행동 |
|---|---|
| **아무 타일**에서 드래그 (파란 칠 안) | **식별** — 3~4칸 박스 |
| **함선 타일**에서 드래그 | **탐지** — 선택 상태와 무관하게 항상 |
| 아군 함선 클릭 | 선택 |

#### 왜 이렇게 갈랐나

충돌하는 곳은 한 군데다 — 이동과 탐지 둘 다 함선 근처에서 시작한다.
그래서 **본체는 탐지, 테두리는 이동**으로 못 박았다. 모드가 없어도 겹치지 않는다.

```
     ┌───┬───┬───┐
     │ 초록 테두리 │  ← 여기서 끌면 이동
     │ ┌───────┐ │
     │ │ 함 선  │ │  ← 여기서 끌면 탐지
     │ └───────┘ │
     └───┴───┴───┘
```

> **부작용 하나** — 이동 박스를 *함선 본체에서* 시작할 수 없게 됐다.
> 엔진(§1.2 #7)은 여전히 허용하지만 화면이 그 칸을 탐지에 내줬기 때문이다.
> 잃는 것은 "지금 자리와 일부 겹치면서 뒤로 한 칸 물러나는" 박스뿐이고,
> 같은 목적지 대부분은 테두리에서 시작해도 닿는다.

#### 남은 키

| | |
|---|---|
| `Tab` | 함선 순환 |
| `Esc` | 선택 취소 |
| `Enter` | 포격 목표가 있으면 발사 / 단어 입력 중이면 실행 |
| `Space` | 일시정지 |

행동 단축키 `1~4` 와 방향키 `WASD` `QEZC` 는 삭제했다. 모드가 없어졌고, 탐지 방향은 드래그가 정한다.

드래그 중에는 결과가 **노란색으로 미리 보인다.** 방향은 자동 스냅되므로 정확히 끌 필요가 없다.

| 칠 | 뜻 |
|---|---|
| 초록 | 이동 — 갈 수 있는 곳 |
| 붉은 | 포격 사거리 |
| 파랑 | 식별 사거리 |
| 노랑 | 지금 조작 중 (드래그 미리보기) |
| 밝은 청록 테두리 | 함선 한 척의 경계 |

자세한 것은 §0.5.

### 0.5 화면 색 체계

**원칙 1 — 의미 하나에 색 하나.** 같은 색을 두 의미에 쓰지 않는다.
**원칙 2 — 겹칠 수 있는 정보는 채널을 나눈다.** 채널이 다르면 한 칸에 동시에 나와도 섞이지 않는다.

함선을 고르기만 해도 **이동 테두리와 포격 사거리가 같이** 뜨는데, 앞의 것은 *링*이고 뒤의 것은 *배경 틴트*라 겹쳐도 구분된다.

#### 채널

| 채널 | 쓰임 | 겹침 |
|---|---|---|
| 배경색 (불투명) | 타일의 기본 상태 | 하나만 |
| 배경 틴트 (반투명) | 사거리 — 포격 / 식별 / 배치구역 | 가능 |
| **함선 외곽선** | **한 척의 경계** | 가능 |
| inset 링 | 이동 가능 테두리 | 가능 |
| 바깥 윤곽선 | 잡아 둔 단어 박스 | 가능 |
| 모서리 삼각형 | 피탐 — 내 칸이 들켰음 | 가능 |
| **중앙 붉은 링** | **포격 목표** | 가능 |
| 중앙 심볼 `✕` | 식별당함 | 가능 |
| 하단 막대 | 체력 | 가능 |
| 아래 밑줄 | 마지막 행(20행) = 상륙 목표 | 가능 |
| 글자 스타일 | 음절 굵게 / 초성 연하게 / 낡음 기울임 | — |

#### 함선 외곽선 **[v0.8 추가]**

배 두 척이 나란히 붙으면 **같은 청록색이 이어져 어디까지가 한 척인지 알 수 없었다.**
그래서 '한 척'을 묶는 전용 채널을 하나 더 뒀다.

**같은 함선이 아닌 쪽에만** 선을 긋는다. 함선 안쪽 이음매에는 선이 없고, 바깥 둘레에만 생긴다.

```
   선 없음                    v0.8
   ┌──┬──┬──┐            ┏━━━━━━━━┓
   │가│나│다│  ← 2척?    ┃가 나 다┃  ← 1척
   ├──┼──┼──┤            ┗━━━━━━━━┛
   │라│마│바│  ← 1척?    ┏━━━━━━━━┓
   └──┴──┴──┘            ┃라 마 바┃  ← 1척
                          ┗━━━━━━━━┛
```

| | 색 |
|---|---|
| 아군 함선 | 밝은 청록 `--hull-mine` |
| 적함 (전지 시점에서만) | 살구 `--hull-foe` |
| **선택된 함선** | **노랑** `--c-act` |

선택 표시를 이 채널에 얹었기 때문에 윤곽선을 하나 더 겹치지 않는다.

> **정보 누출은 없다.** 적함 외곽선은 전지 시점에서만 그린다. 일반 시점에서 접촉(주황) 칸에 외곽선을 그리면 "이 두 칸이 같은 배다"라는, 원래는 완전 해독으로만 얻는 정보가 새기 때문이다.

#### 색상군

| 색 | 의미 | 토큰 |
|---|---|---|
| 회청 | 바탕 · 미탐색 · 초성 판명 | `--t-fog` `--t-known` |
| 청록 | **아군** | `--t-mine` |
| 주황 | **적 접촉** — 지금 거기 있다 | `--t-contact` |
| 황갈 | **적 이탈** — 있었는데 없다 (바랜 주황) | `--t-ghost` |
| 보라 | **잔해** — 영구 지형 | `--t-wreck` |
| 초록 | **이동** — 갈 수 있는 곳 | `--c-move` |
| 적색 | **포격** — 때릴 수 있는 곳 | `--r-fire` |
| 청색 | **식별** — 알아낼 수 있는 곳 | `--r-ident` |
| 노랑 | **조작 중** — 선택 · 드래그 | `--c-act` |
| 진홍 | **위험** — 피탐 · 식별당함 | `--c-warn` |
| 라임 | **승리** — 상륙 줄 | `--c-win` |

행동 셋에 각각 다른 색을 준 것이 요점이다 — **초록=이동, 적색=포격, 청색=식별.** 사거리를 보면 무슨 행동인지 바로 안다.

| 누름 반응 | 없음 | **`scale(.94)`** |
| 좁은 화면 | 없음 | **900px 이하 세로 배치 · 420px 이하 타일 축소** |

전부 `:root` 토큰이다 — `--cell` `--gap` `--tile-r` `--card-r` `--btn-r` `--btn-h`.

> **보드 축소가 먼저였기 때문에 가능했다.** 10×25 에 40px 타일이면 세로 1000px 을 넘는다.
> 8×20 이 되면서 **40px × 20행 = 약 860px** 로 한 화면에 들어오고, 가로는 8 × 40 = 320px 라
> 390px 폰 화면에도 그대로 들어간다.

형태 토큰은 모두 CSS 에만 있다. **열 수만 JS 가 `--cols` 로 넣는다** — 보드 폭이 또 바뀌어도 CSS 는 안 고친다.

> **세로가 900px 인 화면에서는 보드가 스크롤된다** (보드 860px vs 남는 높이 약 710px).
> 두 시점 모두 **자기 1행이 아래쪽**이므로, 보드를 새로 그릴 때 스크롤을 아래로 붙여 둔다 —
> 열면 내 함대와 중립 해역이 보이고, 가려지는 것은 아직 미탐색인 상대 뒷줄뿐이다.
> 플레이 중 스크롤은 건드리지 않는다. 다시 붙는 것은 시점 전환과 새 게임 때뿐이다.

## 1. 이동 — 3 AP

> 한 줄: **새 단어를 밟고 그 단어를 이름으로 삼는다.** 기동·정찰·은폐가 한 번에 일어난다.

### 1.1 조작 흐름 **[v0.8 — 버튼 없음]**

```
함선 클릭  (보드 / 함대 목록 / Tab)
   ↓  이 시점에 두 범위가 같이 보인다
        초록 링   = 이동 시작 가능한 테두리 (본체는 제외 — 탐지 몫)
        진한 초록 = 실제로 합법 박스를 시작할 수 있는 칸
        붉은 칠   = 그 함선의 포격 사거리
   ↓
초록 테두리에서 마우스 누르기
   ↓  끄는 동안 박스가 노랗게 미리 보임 (길이는 함선 길이로 고정)
놓기
   ↓  단어 입력창이 후보를 회색으로 제안 · 자동 포커스
단어 입력 → Enter        (빈칸으로 Enter = 추천 단어)
```

**시작 칸만 제한된다.** 함선 테두리에서 시작해야 한다. **끝 칸은 제한이 없다** — 끄는 방향으로 함선 길이만큼 뻗어 나간다.

> 엔진은 본체에서 시작하는 박스도 받지만(§1.2 #7), 화면이 그 칸을 탐지에 내줬다. 이유는 §0.4.

박스는 가로 또는 세로 직선이며 길이는 **함선 길이와 같다**(3칸함 = 3글자). 읽는 방향은 4방향 모두 가능하다.

### 1.2 전제 조건 (검사 순서)

| # | 조건 | 실패 시 |
|---|---|---|
| 1 | 공통 관문 §0.2 | |
| 2 | 함선이 `식별당함` 상태가 아닐 것 | `식별당함 — 이동 불가 (해제 수단 없음)` |
| 3 | 박스 길이 = 함선 길이 | `단어 박스 길이가 함선 길이와 달라야 함` |
| 4 | 직선 연속 칸일 것 | `직선 연속 박스가 아님` |
| 5 | **지금 있는 칸 집합과 다를 것** (뒤집기 포함) | `자기 자리로는 이동할 수 없음` |
| 6 | 박스의 **모든** 칸이 초성 판명 상태 | `초성 미판명 칸 포함: e14` |
| 7 | **박스의 시작 칸**이 함선으로부터 거리 ≤ 1.5 (본체 또는 테두리) — 화면은 테두리만 내준다 (§0.4) | `박스 시작 칸이 함선에 붙어 있지 않음` |
| 8 | 단어 판정 통과 (§1.5) | 사유별 메시지 |
| 9 | 아군 함선과 겹치지 않을 것 | `아군 함선과 겹침` |

### 1.3 실행 효과 (순서대로)

```
1. AP −3, 쿨타임 = 함선 길이 × 3초
2. 옛 칸 점유 해제 → 새 칸 점유
3. 함명 = 입력한 단어                     ← 핵심
4. 상대가 해독했던 음절 → 옛 자리에 '낡은 정보'로 이전 (§1.6)
5. 함선 타일 + 반지름 1.5 이내 전부 정보 획득
     · 초성 판명 (영구)
     · 적함이 있으면 접촉(주황) — 상대에게도 피탐으로 기록
     · 전에 접촉이었는데 비어 있으면 이탈(?)
6. 상륙 판정 — 타일 하나라도 자기 기준 마지막 행(20행)이면 즉시 승리
```

3칸 함선이 이동하면 **15칸**이 한 번에 밝혀진다 (5×3).

### 1.4 충돌 — 양쪽 다 침몰한다 **[v0.7 변경]**

이동 박스가 적함과 겹치면 **들이받은 것으로 처리되어 두 함선이 모두 침몰한다.**

```
1. 이동은 그대로 실행된다 (함선이 박스로 옮겨지고 함명이 바뀐다)
2. 이동한 함선이 먼저 침몰 → 자기 박스 전체에 함명 각인
3. 충돌당한 적함들이 침몰 → 자기 타일에 각인
   단, 이미 각인된 칸은 덮어쓰지 않는다
4. 전멸 판정 (양쪽이 동시에 전멸하면 무승부)
```

**겹친 칸의 글자는 이동한 쪽의 것으로 고정된다.** 먼저 각인하기 때문이다.

```
P1 3칸함이 「게괴구」로 (d5,e5,f5) 에 돌진
P2 4칸함 「가나다라」가 (c5,d5,e5,f5) 를 점유 중

결과  c5 = 가   ← P2 것 (안 겹침)
      d5 = 게   ← P1 것 (겹침 — 이동한 쪽이 이긴다)
      e5 = 괴
      f5 = 구
```

**이 규칙이 만드는 것**

| | |
|---|---|
| 자폭 교환 | 3칸함(HP 6)으로 4칸함(HP 10)을 끌고 죽을 수 있다. 포격으로는 오래 걸릴 일 |
| 돌파 저지 | 상륙하려는 배를 몸으로 막는 수단이 생긴다 |
| 지형 설계 | 죽으면서 **내가 고른 글자**를 상대 진영에 박아 넣는다 |
| 위험 | 모르고 들이받으면 내 배만 손해다. 적함 위치를 알고 하는 선택이어야 한다 |

### 1.5 단어 판정 파이프라인

```
① 길이     단어 글자 수 = 박스 칸 수
② 문자     완성형 한글만
③ 칸별 대조  잔해 칸  → 각인된 음절과 정확히 일치
            그 외    → 초성만 일치
④ 사전     등재어인가
```

경음은 대체 불가. 타일이 `ㄲ`이면 단어도 `ㄲ`이어야 한다.

### 1.6 해독 정보는 즉시 지워지지 않는다 **[v0.7 변경]**

이전에는 함선이 이동하면 상대가 해독한 음절이 **그 즉시** 사라졌다. 이제는 그렇지 않다.

```
이동 시  →  상대가 해독했던 음절이 '옛 자리'에 낡은 정보로 남는다
            (화면에 기울임체 + 점선 테두리로 표시)
상대가 그 칸을 다시 관측하면  →  폐기
```

접촉(주황)이 재관측 전까지 낡은 채로 남는 것과 같은 방식이다. **정보는 갱신될 때까지 낡을 뿐 사라지지 않는다.**

- 낡은 음절은 **표시만** 된다. 포격 정밀 보너스에는 쓰이지 않는다
- 잔해가 생기면 잔해 글자가 우선한다

### 1.7 전략 메모

이동은 **세 가지를 한꺼번에 사는** 행동이라 3 AP다.

| 측면 | 효과 |
|---|---|
| 기동 | 위치 이동 + 상륙 진척 |
| 정찰 | 주변 15칸 자동 판명 → 다음 이동의 연료 |
| **은폐** | 함명 교체 → 상대의 해독 정보가 통째로 무효 |

움직이려면 목적지 초성을 알아야 하고, 초성을 알려면 탐지하거나 이동해야 한다. 이 순환이 게임의 엔진이다.

## 2. 탐지 — 2 AP **[v0.8 개편]**

> 한 줄: **한 방향으로 쐐기 13칸을 밝힌다.** 이동 다음으로 넓고, 위치가 노출되지 않는다.

### 2.0 무엇이 바뀌었나

| | v0.7 | v0.8 |
|---|---|---|
| AP | 1 | **2** |
| 모양 | 직선 5칸 | **쐐기 13칸** (정면 5 + 좌우 각 4) |
| 방향 | 8방향 | **4방향** (상하좌우) |
| 칸당 AP | 5.0 | **6.5** |

직선 1줄로는 이동 박스(가로·세로 어느 쪽이든 함선 길이)의 **밑작업이 되지 못했다.**
탐지로 연 줄과 직각인 방향으로 가려면 다시 탐지해야 했다. 쐐기는 **폭이 3칸**이라 그 한 번으로 다음 이동의 후보가 실제로 생긴다.

대각을 없앤 것은 값이 안 나와서다 — 이동 박스도 포격 조준도 전부 상하좌우 기준인데, 대각 탐지가 여는 줄은 어느 쪽으로도 잘 이어지지 않았다. 선택지만 늘리고 쓸모는 없었다.

### 2.1 모양

원점(누른 함선 타일)에서 방향 `d` 로:

```
정면   d×1 … d×5          5칸
좌우   d×1±⊥ … d×4±⊥      각 4칸
──────────────────────────────
                          13칸
```

```
        ㅁㅁㅁㅁ
   ▣ →  ㅁㅁㅁㅁㅁ          ▣ = 원점 (자기 함선 타일 · 판명 대상 아님)
        ㅁㅁㅁㅁ
```

- **좌우 날개는 원점 쪽에 맞춰 정렬된다.** 정면만 한 칸 더 뻗어 끝이 뾰족하다.
- 원점 바로 옆의 두 칸(`▣` 위아래)은 **포함되지 않는다.** 날개도 `d×1` 부터 시작한다.
- 보드 밖은 그냥 버려진다. 가장자리에서 바깥을 향해 쏘면 손해다.

```
상수  BALANCE.scan = { length: 5, flank: 4 }
구현  WS.game.scanCells(fromIdx, dirKey)
```

### 2.2 조작 흐름 **[v0.8 — 버튼 없음]**

```
함선 타일에서 마우스 누르기        ← 선택 상태와 무관하다
   ↓  끄는 방향으로 쐐기 13칸이 노랗게 미리 보임
놓기  →  즉시 실행
```

- **함선을 미리 고를 필요가 없다.** 누른 칸의 함선이 그 자리에서 쏜다.
- 방향은 드래그 벡터에서 **4방향으로 자동 스냅**된다. 많이 끈 축이 이긴다.
- **원점은 내가 누른 타일**이다. 함선의 어느 칸에서 쏠지 직접 고른다.
- 방향 버튼과 `WASD`·`QEZC` 단축키는 삭제했다.

### 2.3 전제 조건

| # | 조건 | 실패 시 |
|---|---|---|
| 1 | 공통 관문 §0.2 | |
| 2 | 원점이 그 함선의 점유 타일 | `자기 함선이 점유한 타일을 골라야 함` |
| 3 | 방향이 `N S E Wd` 중 하나 | `방향 오류 (상하좌우만 가능 — 대각 폐지)` |

이동과 달리 **식별당한 함선도 탐지할 수 있다.** 묶인 배가 할 수 있는 몇 안 되는 일이다.

### 2.4 실행 효과

```
1. AP −2, 쿨타임 5초
2. 쐐기 안의 모든 칸:
     · 초성 판명 (영구)
     · 적함이 있으면 접촉(주황) + 상대에게 피탐 기록
     · 전에 접촉이었는데 비어 있으면 이탈(?)
3. 보드 밖 칸은 버려진다 — 남은 사거리는 회수되지 않는다
```

가장자리 손실이 v0.7보다 커졌다. 폭이 3칸이라 **옆면이 벽에 닿기만 해도 날개 절반을 잃는다.**

```
y22 에서 북쪽으로 (보드 높이 25)
   정면  y23 y24                        2칸
   날개  (x±1, y23) (x±1, y24)          4칸
   ────────────────────────────────────────
   13칸 중 6칸만 남는다
```

### 2.5 전략 메모

- **폭 3칸**이 요점이다. 이동 박스는 가로든 세로든 설 수 있으므로, 폭이 있어야 다음 수가 생긴다.
- 위치가 노출되지 않는다. 포격과 달리 반동이 없다.
- 쿨타임 5초로 여전히 가장 짧다. 막는 것은 AP 쪽이다 — 2 AP는 5초치 수입이라 쿨타임과 거의 같아졌다.
- 이동(15칸)과 비교하면 칸 수는 87%인데 AP는 2/3다. 다만 이동은 **함명 교체와 전진**을 같이 사므로 여전히 다른 물건이다.

| | 이동 | 탐지 | 차이 |
|---|---|---|---|
| 여는 칸 | 15 | 13 | −13% |
| AP | 3 | 2 | −33% |
| 칸당 AP | 5.0 | 6.5 | 탐지가 비싸다 |

이동이 칸당으로는 더 싸다. 그런데도 탐지가 필요한 것은 **이동에는 자격이 필요**하기 때문이다 — 목적지가 전부 판명돼 있어야 한다. 탐지는 그 자격을 만드는 행동이고, 순서상 언제나 먼저 온다.

## 3. 식별 — 2 AP

> 한 줄: **적 함명을 추리해서 맞힌다.** 성공하면 그 배는 영원히 못 움직인다.
> 이 게임에서 가장 언어적이고 가장 무거운 행동.

### 3.1 조작 흐름 **[v0.8 — 선택을 풀면 식별]**

```
함선 선택 없음  (Esc · 사거리 밖 클릭 · 처음부터)
   ↓  파랑 = 어느 함선이든 거리 7 이내 + 초성 판명된 칸
   ↓
파란 칸에서 마우스 누르기
   ↓  끄는 방향으로 3~4칸 박스가 노랗게 미리 보임
      (많이 끌면 4칸, 적게 끌면 3칸)
놓기
   ↓
적 함명을 추측해 입력 → Enter
```

**함선 선택 단계가 없다.** 함대 전체의 사거리가 기준이다.
그래서 식별은 **선택을 푼 상태의 기본 동작**이 됐다 — 버튼 대신 '선택 없음'이 모드 역할을 한다.
함선을 고른 상태에서는 식별할 수 없다. 먼저 `Esc` 를 누르거나 사거리 밖을 클릭한다.

| | |
|---|---|
| 시작 칸 | 살아 있는 **어느 함선이든** 거리 7 이내 + 초성 판명 |
| 끝 칸 | 제한 없음 (박스 길이 3~4만 지키면 된다) |
| 쿨타임 | **시작 칸을 사거리에 두는 함선 중 가장 가까운 것**이 8초 쿨타임을 진다 |

사거리 안의 함선이 전부 쿨타임이면 거부된다 — `사거리 안의 함선이 전부 쿨타임 (n초 남음)`.

> 함선을 고르지 않게 했지만 **자원 모델은 그대로**다. 여전히 함선 한 척이 쿨타임을 지므로, 함대가 크면 식별을 더 자주 할 수 있다. 어느 배가 담당했는지는 로그에 남는다 — `식별(P1-3-L3): 「바다새」 …`

### 3.2 무엇을 추측하는가

적 함선은 **마지막으로 이동할 때 쓴 단어**를 이름으로 지니고 있다. 그 단어를 맞히는 것이다.

```
적함이 (c8, c9, c10) 을 차지하고 함명이 「바다새」라면
  → 그 칸들의 초성은 ㅂ ㄷ ㅅ
  → 내가 「바다새」라고 입력하면 3칸 전부 해독
  → 「바람새」라고 입력하면 '바'와 '새' 2칸만 해독
```

**칸별 독립 판정**이라 부분 적중이 쌓인다.

### 3.3 전제 조건

| # | 조건 | 실패 시 |
|---|---|---|
| 1 | 공통 관문 §0.2 | |
| 2 | 박스 길이 3~4칸 | `식별 박스는 3~4칸` |
| 3 | 직선 연속 | `직선 연속 박스가 아님` |
| 4 | 모든 칸이 초성 판명 | `초성 미판명 칸 포함` |
| 5 | **시작 칸**이 어느 함선이든 거리 ≤ 7 | `박스 시작 칸이 어느 함선의 사거리에도 들어오지 않음` |
| 6 | 단어 판정 통과 (§1.5) | 사유별 메시지 |

### 3.4 실행 효과 — 세 가지가 독립적으로 일어난다

```
AP −2, 쿨타임 8초

① 함선 판정
   박스 안에 적함이 있으면 → 그 함선 전부에 「식별당함」
     · 이동 영구 불가 (해제 수단 없음)
     · 입는 피해 3배
     · 양측 화면에 적색 ✕
   적함이 없으면 → 아무 일도 없음 (AP만 소모)

② 음절 판정 — 칸마다 따로
   for 각 칸:
     적함이 있고 && 입력 음절 == 그 칸의 함명 음절
       → 그 음절 해독 (내 지식에만 기록)
   전 음절을 해독하면 → 그 함선의 실루엣 전체 공개
                        (길이·방향·위치가 확정된다)

③ 접촉 확정
   적함 있는 칸 → 접촉(주황) + 상대에게 피탐
   빈 칸        → 빈 칸으로 확정
```

### 3.5 해독한 정보는 휘발성이다

| 상황 | 해독 정보 |
|---|---|
| 대상 함선이 **이동** | **전부 소멸** — 새 단어를 쓰니 이름이 바뀐다 |
| 대상 함선이 **침몰** | 잔해 각인으로 승격 (영구·양측 공개) |
| 그 외 | 유지 |

**단, 식별당한 배는 이동할 수 없다.** 그래서 한 번 식별에 성공하면 해독 정보가 그 배가 죽을 때까지 유효하다. 디버프와 정보가 서로를 잠근다.

### 3.6 전략 메모

식별은 문 두 개를 동시에 연다.

1. **묶는다** — 이동 불가. 상륙 돌파는 그 순간 끝난다
2. **보이게 한다** — 식별당한 함선만 체력 바와 피해량이 보인다 (§4.5)

2 AP의 값이 여기서 나온다. 추리 난이도는 사전이 결정한다 — 초성 `ㅂㄷㅅ`에 맞는 3글자 명사가 몇 개인지가 곧 적중률이다.

> **[우려]** 해제 수단이 없어 매우 강력하다. 특히 상륙 돌파와 정면으로 충돌한다 — 돌파 주자가 적진에서 한 번 식별당하면 영영 멈추고, 상대는 천천히 잡으면 된다. 방어가 공격을 압도할 수 있다. 밸런스 단계의 관측 대상이다. (GDD §8.1)

## 4. 포격 — 1 AP

> 한 줄: **한 칸을 때린다.** 대신 반드시 내 위치가 하나 드러난다.

### 4.1 조작 흐름 **[v0.8 — 두 단계]**

```
함선 클릭
   ↓  붉은 칠 = 그 함선의 사거리
붉은 칸 클릭  →  목표 지정 (붉은 링이 찍힌다)
   ↓
「포격」 버튼  또는  Enter  또는  같은 칸 한 번 더 클릭
   ↓
발사
```

**즉발에서 2단계로 바꿨다.** 사거리 안을 클릭하는 것이 '선택 취소'와 같은 동작(클릭)이 되었기 때문에, 오조작으로 AP를 날리지 않도록 확인 단계를 뒀다.

사거리 **밖**을 클릭하면 발사가 아니라 **선택 취소**다. 붉은 칠이 곧 "여기까지가 내 손이 닿는 곳"의 경계선이다.

### 4.2 전제 조건

| # | 조건 | 실패 시 |
|---|---|---|
| 1 | 공통 관문 §0.2 | |
| 2 | 목표가 사거리 안 (3칸함 3 / 4칸함 5) | `사거리 초과 (길이 3 → 3칸)` |
| 3 | 아군 함선이 아닐 것 | `아군 함선은 조준 불가` |

**목표 칸이 미탐색이어도 쏠 수 있다.** 맹목 사격이 허용된다.

### 4.3 피해 계산

```
dmg = 1
if (그 칸의 음절을 내가 안다)   dmg += 1     ← 정밀 사격
if (피격 함선이 식별당함)       dmg *= 3
```

곱셈이 바깥이라 조합이 크게 보상받는다.

| 상황 | 피해 |
|---|---|
| 맹목 사격 | 1 |
| 음절 해독한 칸 / 잔해 칸 | 2 |
| 식별당한 함선 | 3 |
| **식별 + 해독** | **6** |

3칸 함선(HP 3)은 식별당한 상태에서 정밀 포격 **한 방**에 침몰한다.

"그 칸의 음절을 안다" = 식별로 해독했거나, 잔해 칸이거나. 잔해는 항상 공개이므로 **잔해 지대는 영구 +1 피해 구역**이다.

### 4.4 실행 효과

```
AP −1, 쿨타임 6초

명중  → HP 감소, 그 칸 접촉(주황) 확정 (양측)
빗나감 → 그 칸 빈 칸으로 확정
HP ≤ 0 → 침몰 (§4.6)

반동 (명중·빗나감 무관)
  내 함선 타일 중 상대에게 아직 노출 안 된 칸 하나를
  랜덤으로 골라 상대에게 공개한다.
  전부 노출된 상태면 아무 일도 없다.
```

### 4.5 무엇이 보이는가 — 식별 여부가 갈랐다

| 대상 | 사수가 보는 것 |
|---|---|
| 식별하지 않은 적함 | **"명중" 만.** 피해량도 HP도 안 보임 |
| **식별당한** 적함 | 피해량 + 체력 바 |
| 자기 함선 | 항상 전부 |

몇 대 때렸는지 모르면 언제 죽일 수 있는지도 모른다. 그래서 **맹목 포격만으로는 적을 계획적으로 갉아먹을 수 없다.** 죽이려면 먼저 식별해야 한다.

다만 명중하면 그 칸에 적함이 있다는 것은 알게 되므로, **정찰 수단으로는 여전히 쓸 수 있다.**

### 4.6 침몰

```
그 함선의 함명이 점유 타일에 그대로 각인된다.

for 각 타일:
  잔해로 전환 (영구·양측 공개)
  점유 해제 — 더 이상 함선으로 판별되지 않는다
  양측 초성 판명 + 접촉 해제
```

잔해 칸의 성질:

| 항목 | 내용 |
|---|---|
| 글자 | **영구 고정.** 그 칸을 지나는 모든 단어가 **정확한 음절**을 써야 한다 |
| 통과 | 가능. 함선이 올라설 수 있다 |
| 표적 | 아님. 식별·포격 대상이 되지 않는다 |
| 포격 | 음절이 공개 상태라 항상 정밀(+1) |

```
함명 「별바다」 함선 침몰 → 별 / 바 / 다 각인
다른 함선이 '다' 칸을 지나려면
    다슬기  가능   ('다' 일치)
    도시락  불가   (ㄷ만 맞고 '다'가 아님)
```

침몰이 쌓일수록 보드가 딱딱해진다. 항로가 좁아지고, 잔해 지대는 피해 +1 구역이 된다. **침몰지가 위험지대로 변해 전장을 재편한다.**

### 4.7 전략 메모

- **쏘면 들킨다.** 반동은 명중 여부와 무관하다. 빗나간 사격은 순손실이다.
- 4칸함(사거리 5)은 같은 행에서는 보드 폭 전체를 덮지만, 세로로는 5칸까지다.
- 쿨타임 6초라 연타는 어렵다. 3칸함 하나를 확실히 잡으려면 식별 후 정밀 한 방이 낫다.

| | 이동 | 탐지 | 식별 | 포격 |
|---|---|---|---|---|
| AP | 3 | **2** | 2 | 1 |
| 쿨타임 | 9~12초 | 5초 | 8초 | 6초 |
| 사거리 | 인접 1.5 | **4방향 쐐기 13칸** | 7 | 3 / 5 |
| 단어 필요 | 예 (함선 길이) | 아니오 | 예 (3~4글자) | 아니오 |
| **조작** | **테두리 드래그** → 단어 | **함선 위 드래그** | **선택 없이 드래그** → 단어 | **사거리 안 클릭 → 포격** |
| 함선 선택 필요 | 예 | **아니오** (누른 칸의 함선이 쏜다) | **아니오** (선택이 없어야 한다) | 예 |
| 내 위치 노출 | 아니오 | 아니오 | 아니오 | **예 (반동)** |
| 식별당해도 가능 | **아니오** | 예 | 예 | 예 |
| 정보 획득 | 15칸 초성 | **13칸 초성** | 접촉 확정 + 음절 | 접촉 1칸 |
| 주 효과 | 이동·은폐 | 초성 확보 | 영구 이동 봉쇄 | 피해 |

### 조작이 겹치지 않는 이유

```
              함선 선택됨          선택 없음
함선 타일   →  탐지                 탐지
초록 테두리 →  이동                  —
붉은 사거리 →  포격 목표             식별 (파란 칠이면)
그 밖       →  선택 취소             식별 (파란 칠이면)
```

한 칸은 상태마다 뜻이 하나뿐이다. 그래서 모드 버튼이 필요 없다.

### 행동 사이의 의존 관계

```
탐지 ──초성──→ 이동 ──전진──→ 상륙 승리
                 │
                 └─접촉─→ 식별 ──봉쇄·해독──→ 포격 ──→ 침몰 ──→ 전멸 승리
                                                          │
                                                          └─→ 잔해(지형 변화)
```

- 이동하려면 **먼저 탐지**해야 한다 (목적지 전부가 판명돼야 함)
- 식별하려면 **먼저 접촉**이 있어야 유용하다 (없으면 AP만 날린다)
- 효율적으로 죽이려면 **먼저 식별**해야 한다 (피해 3배 + 체력이 보임)
