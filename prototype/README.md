# WordShip — 0단계 동작 검증 프로토타입 (v0.5 실시간)

목표는 하나다. **규칙이 의도대로 발동하는가.**
밸런스가 좋은지, 화면이 예쁜지, 사전이 제대로인지는 보지 않는다.

## 실행

`prototype/index.html`을 브라우저로 열면 된다. 빌드도 서버도 필요 없다 (ES 모듈 대신 일반 `<script>`를 쓴 이유가 이것이다).

```
prototype/
  index.html
  css/style.css
  src/core.js    한글 유틸 · PRNG · 밸런스 상수 · 사전
  src/game.js    엔진 — 보드 / 지식 3종 / 행동 4종 / 실시간 시계 / 승리 판정
  src/tests.js   자가 검증 67건 + 랜덤 봇
  src/ui.js      최소 UI
```

## 자가 검증

화면 오른쪽 위 **자가 검증** 버튼. 또는 Node로:

```bash
node -e "global.window=global;global.performance=require('perf_hooks').performance;
['core','game','tests'].forEach(f=>require('./src/'+f+'.js'));
const r=window.WS.tests.runAll();
r.results.filter(t=>!t.ok).forEach(t=>console.log('FAIL',t.name,'::',t.detail));
console.log(r.pass+'/'+r.total+' pass');"
```

현재 **67/67 통과**.

검증 범위 — 함대 구성(4칸3·3칸5) / 보드 생성(초성만·8:2·데드존·결정론) / 준비(구역 공개·자동 배치·함명 초성 일치) / **AP 시간 회복·상한 10·비용** / **함선별 쿨타임**(탐지 5s·이동 길이×3s) / **실시간 동시 행동** / 이동(길이·초성·미지칸·인접·**함명 교체**·**상대 지식 소멸**·**자기 자리 금지**·**동일 함명 허용**·충돌) / 탐지(5칸·클리핑) / 식별(디버프·칸별 부분 적중·완전 해독·3~4칸·사거리) / **식별당함 영구** / 포격(1·2·3·6 피해·**피해 가시성**·맹목 사격·반동·아군 금지) / 침몰(함명 각인) / 잔해(정확 음절 강제) / **상륙 승리**(1칸 진입·P1P2·쿨타임 제한) / 전멸 / 지식 레이어(미러링·GHOST·영구vs휘발·로그 분리) / 통합(봇 대국·불변식).

## 조작

**실시간이라 혼자 양측을 조작할 수 없다.** 기본값은 `조작 = P1, 상대 = 봇`.

> 최종 목표는 **버튼을 없애고 보드 위에서만** 조작하는 것이다. 지금은 과도기 — 드래그가 주 조작이고 버튼은 남아 있다.

기본 흐름은 **함선 고르기 → 행동 고르기 → 보드에서 드래그**다.

| 행동 | 조작 |
|---|---|
| **이동** (AP 3) | `1` → **함선 본체/테두리(초록)에서 드래그** → 놓고 단어 입력 → `Enter` |
| **탐지** (AP 1) | `2` → **함선 타일에서 원하는 방향으로 드래그** → 놓으면 즉시 실행 |
| **식별** (AP 2) | `3` → **함선 선택 없이** 파란 범위 안에서 드래그 (3~4칸) → 적 함명 추측 → `Enter` |
| **포격** (AP 1) | `4` → 파란 범위 안 칸 클릭 → 즉시 |

- 드래그 중 결과가 **노랗게 미리 보인다.** 방향은 자동 스냅되므로 대충 끌어도 된다.
- 드래그 대신 **두 번 클릭**(시작 → 끝)해도 되고, 버튼도 아직 동작한다.
- 단어 입력창은 후보를 회색으로 제안한다. **빈칸으로 `Enter`** 치면 그 후보로 실행된다.
- 행동 버튼이 흐리면 지금 불가. 눌러 보면 이유를 알려준다.
- `Tab` 함선 순환 · `Esc` 취소 · `Space` 일시정지.

거리는 **유클리드(직선 거리)** 라 사거리 범위가 원형이다.

시계 줄에서 **일시정지 / 속도(1×·2×·4×) / 조작 플레이어 / 봇 on·off** 를 바꿀 수 있다.
관전만 하려면 P1·P2 둘 다 봇으로 켜면 된다.
**전지 시점**을 켜면 양측 정보와 로그가 전부 보인다.

## 화면 읽는 법

25행이 항상 **위쪽**이다 (= 상륙 목표, 초록 밑줄). 1행이 아래쪽 내 진영.
AP는 상태줄의 보라색 막대 10칸.

**함선을 고르기만 해도** 그 함선의 이동 테두리(초록 링)와 포격 사거리(붉은 칠)가 같이 보인다.

색은 **의미 하나에 색 하나**로 정리돼 있고, 겹칠 수 있는 정보는 **채널**(배경색 / 틴트 / 링 / 윤곽 / 모서리 / 심볼)을 나눠 섞이지 않게 했다. 전체 표는 [docs/ACTIONS.md §0.5](../docs/ACTIONS.md).

| 행동 | 색 |
|---|---|
| 이동 | **초록** |
| 포격 | **붉은** |
| 식별 | **파랑** |
| 지금 조작 중 | **노랑** |

| 보이는 것 | 뜻 |
|---|---|
| 어두운 빈칸 | 미탐색 |
| 회청 + 초성 1자 | 초성 판명 |
| 청록 | 아군 함선 |
| 주황 | 접촉 — 적함 확인 |
| 황갈 `?` | 이탈 — 있었는데 지금은 없음 |
| 보라 | 잔해 — 글자 영구 고정 |
| 기울임 + 점선 | 낡은 정보 — 예전에 해독한 음절 |
| 붉은 모서리 삼각형 | 피탐 — 내 칸이 들켰음 |
| 붉은 ✕ | 식별당함 (영구 이동 불가) |
| 칸 아래 가는 막대 | 체력 — 아군은 항상, 적은 식별했을 때만 |

색을 바꾸려면 `css/style.css` 맨 위 `:root` 토큰만 고치면 된다.

### 허용 사전을 기본값으로 둔 근거 (측정함)

스텁 사전(98단어)으로 자동 배치를 8개 시드에서 시도한 결과:

```
스텁 사전 자동 배치: 성공 0 / 실패 8  (길이 5 — 사전에 맞는 단어를 못 찾음)
```

**한 척도 못 놓았다.** 초성 조합에 맞는 단어가 없기 때문이다. 이 측정이 v0.5에서 **5칸 함선을 폐지한 직접적 근거**가 됐다. 사전 없이는 게임이 시작조차 안 되므로 0단계에서는 초성 일치만 보고 통과시킨다. 사전은 §6.4 파이프라인으로 따로 빌드해 나중에 끼우는 독립 부품이다.

UI의 `스텁 사전 (엄격)` 옵션은 **엄격 경로가 동작하는지 보기 위한 것**이고, 선택하면 자동 배치가 실패하는 게 정상이다.

## 랜덤 봇 대국 통계 (허용 사전, 10판)

```
상륙 10 / 전멸 0 / 미결착 0 · 평균 181초
최단 상륙: 15회 이동 / 133초 (한 척만 집중해 밀었을 때)
```

두 가지가 보인다.

1. **"개빠른 상륙"은 규칙상 불가능하다.** 이동 쿨 9초 + AP 3(=7.5초치 수입)이 하한을 만든다.
2. **전멸 승리가 0건이다.** 랜덤 봇이 전투를 못한다는 점을 감안해도, 승리 경로 하나가 작동하지 않을 가능성이 있다. 밸런스 단계의 1번 관측 대상.

### 봇을 고치며 알게 된 것

첫 봇은 **15분 동안 한 척도 자기 진영을 벗어나지 못했다.** 이동이 3 AP인데 탐지·포격이 1 AP라, 탐욕적으로 굴리면 싼 행동들이 AP를 계속 빨아가 이동에 필요한 3을 영영 못 모은다. 이동분을 먼저 떼어 두도록 고치자 바로 전진했다.

이건 봇 버그였지만 **실시간 전환이 만든 실제 플레이 포인트**이기도 하다. 턴제에서는 AP가 매 턴 초기화돼 안 쓰면 손해였는데, 이제는 **아끼는 것이 전략**이다.
