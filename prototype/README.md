# WordShip — 0단계 동작 검증 프로토타입 (v0.9 축소 보드)

목표는 하나다. **규칙이 의도대로 발동하는가.**
밸런스가 좋은지, 화면이 예쁜지, 사전이 제대로인지는 보지 않는다.

## 실행

`prototype/index.html`을 브라우저로 열면 된다. 빌드도 서버도 필요 없다 (ES 모듈 대신 일반 `<script>`를 쓴 이유가 이것이다).

```
prototype/
  index.html
  css/style.css
  src/core.js    한글 유틸 · PRNG · 밸런스 상수 · 사전
  src/game.js    엔진 — 보드 / 지식 3종 / 행동 4종 / 실시간 시계 / 승리 판정
  src/tests.js   자가 검증 69건 + 랜덤 봇
  src/ui.js      최소 UI
```

## 자가 검증

화면 오른쪽 위 **자가 검증** 버튼. 또는 Node로:

```bash
node -e "global.window=global;global.performance=require('perf_hooks').performance;
['core','game','tests'].forEach(f=>require('./src/'+f+'.js'));
const r=window.WS.tests.runAll();
r.results.filter(t=>!t.ok).forEach(t=>console.log('FAIL',t.name,'::',t.detail));
console.log(r.pass+'/'+r.total+' pass');"
```

현재 **69/69 통과**.

검증 범위 — 함대 구성(4칸1·3칸4) / **보드 규격(8×20·중립 4행·a~h)** / 보드 생성(초성만·8:2·데드존·결정론) / 준비(구역 공개·자동 배치·함명 초성 일치) / **AP 시간 회복·상한 10·비용** / **함선별 쿨타임**(탐지 5s·이동 길이×3s) / **실시간 동시 행동** / 이동(길이·초성·미지칸·인접·**함명 교체**·**상대 지식 소멸**·**자기 자리 금지**·**동일 함명 허용**·충돌) / 탐지(**쐐기 13칸**·**대각 거부**·클리핑) / 식별(디버프·칸별 부분 적중·완전 해독·3~4칸·사거리) / **식별당함 영구** / 포격(1·2·3·6 피해·**피해 가시성**·맹목 사격·반동·아군 금지) / 침몰(함명 각인) / 잔해(정확 음절 강제) / **상륙 승리**(1칸 진입·P1P2·쿨타임 제한) / 전멸 / 지식 레이어(미러링·GHOST·영구vs휘발·로그 분리) / 통합(봇 대국·불변식).

## 조작

**실시간이라 혼자 양측을 조작할 수 없다.** 기본값은 `조작 = P1, 상대 = 봇`.

> **[v0.8] 행동 버튼을 없앴다.** 무슨 행동인지는 **어디서 드래그를 시작했는가**가 정한다.
> 남은 버튼은 「포격」 하나 — 목표를 찍은 뒤 누르는 확인 버튼이다.

상태는 둘뿐이다. **함선을 골랐는가, 안 골랐는가.**

### 함선을 고른 상태

클릭하면 **초록 테두리**(이동)와 **붉은 칠**(포격 사거리)이 같이 뜬다.

| 조작 | 행동 |
|---|---|
| **함선 타일** 드래그 | **탐지** (AP 2) — 상하좌우, 쐐기 13칸 |
| **초록 테두리** 드래그 | **이동** (AP 3) — 놓고 단어 입력 → `Enter` |
| **붉은 칸** 클릭 → 「포격」 | **포격** (AP 1) — 같은 칸 한 번 더 눌러도 발사 |
| **사거리 밖** 클릭 | **선택 취소** |

### 함선을 안 고른 상태

| 조작 | 행동 |
|---|---|
| **파란 칸** 드래그 | **식별** (AP 2) — 3~4칸, 적 함명 추측 → `Enter` |
| **함선 타일** 드래그 | **탐지** — 선택 상태와 무관하게 항상 |
| 아군 함선 클릭 | 선택 |

**본체 = 탐지, 테두리 = 이동.** 이 한 줄이 모드를 대신한다.

- 드래그 중 결과가 **노랗게 미리 보인다.** 방향은 자동 스냅되므로 대충 끌어도 된다.
- 단어 입력창은 후보를 회색으로 제안한다. **빈칸으로 `Enter`** 치면 그 후보로 실행된다.
- `Tab` 함선 순환 · `Esc` 선택 취소 · `Enter` 포격 · `Space` 일시정지.
- 행동 단축키 `1~4` 와 방향키 `WASD`·`QEZC` 는 삭제했다.

거리는 **유클리드(직선 거리)** 라 사거리 범위가 원형이다.

시계 줄에서 **일시정지 / 속도(1×·2×·4×) / 조작 플레이어 / 봇 on·off** 를 바꿀 수 있다.
관전만 하려면 P1·P2 둘 다 봇으로 켜면 된다.
**전지 시점**을 켜면 양측 정보와 로그가 전부 보인다.

## 화면 읽는 법

**보드는 8 × 20** (가로 `a`~`h`). 자기 진영 8×8 + 중립 4행 + 상대 진영 8×8.
20행이 항상 **위쪽**이다 (= 상륙 목표, 초록 밑줄). 1행이 아래쪽 내 진영.

**타일은 40px 스도쿠 규격 [v0.9].** `DailySudoku` 의 타일 생김새를 가져왔다 — 둥근 타일, 카드형 보드, 누르면 들어가는 버튼. **색 체계는 그대로다** (이유는 [docs/ACTIONS.md §0.6](../docs/ACTIONS.md)). 900px 이하에서는 패널이 보드 아래로 내려가고, 420px 이하에서는 타일이 36px로 줄어 **390px 폰 화면에도 보드가 통째로 들어간다.**
AP는 상태줄의 보라색 막대 10칸.

**함선을 고르기만 해도** 그 함선의 이동 테두리(초록 링)와 포격 사거리(붉은 칠)가 같이 보인다.

**함선마다 외곽선이 그려진다 [v0.8].** 배가 나란히 붙어도 어디까지가 한 척인지 보인다 — 같은 함선이 아닌 쪽에만 선을 긋기 때문이다. 선택한 함선은 이 선이 노랗게 바뀐다. (적함 외곽선은 전지 시점에서만 그린다. 일반 시점에서 그리면 "이 두 칸이 같은 배"라는 정보가 샌다.)

색은 **의미 하나에 색 하나**로 정리돼 있고, 겹칠 수 있는 정보는 **채널**(배경색 / 틴트 / 링 / 윤곽 / 모서리 / 심볼)을 나눠 섞이지 않게 했다. 전체 표는 [docs/ACTIONS.md §0.5](../docs/ACTIONS.md).

| 행동 | 색 |
|---|---|
| 이동 | **초록** |
| 포격 | **붉은** |
| 식별 | **파랑** |
| 지금 조작 중 | **노랑** |

| 보이는 것 | 뜻 |
|---|---|
| 어두운 빈칸 | 미탐색 |
| 회청 + 초성 1자 | 초성 판명 |
| 청록 | 아군 함선 |
| 주황 | 접촉 — 적함 확인 |
| 황갈 `?` | 이탈 — 있었는데 지금은 없음 |
| 보라 | 잔해 — 글자 영구 고정 |
| 기울임 + 점선 | 낡은 정보 — 예전에 해독한 음절 |
| 붉은 모서리 삼각형 | 피탐 — 내 칸이 들켰음 |
| 붉은 ✕ | 식별당함 (영구 이동 불가) |
| 칸 아래 가는 막대 | 체력 — 아군은 항상, 적은 식별했을 때만 |
| 밝은 청록 외곽선 | 아군 함선 한 척의 경계 |
| 노란 외곽선 | 선택된 함선 |
| 붉은 링 | 지정된 포격 목표 |

색도 형태도 전부 `css/style.css` 맨 위 `:root` 토큰이다 — 색은 `--t-*` `--c-*` `--r-*`, 형태는 `--cell` `--gap` `--tile-r` `--card-r` `--btn-r` `--btn-h`. 보드의 **열 수만** JS 가 `--cols` 로 넣는다.

### 허용 사전을 기본값으로 둔 근거 (측정함)

스텁 사전(98단어)으로 자동 배치를 8개 시드에서 시도한 결과:

```
스텁 사전 자동 배치: 성공 0 / 실패 8  (길이 5 — 사전에 맞는 단어를 못 찾음)
```

**한 척도 못 놓았다.** 초성 조합에 맞는 단어가 없기 때문이다. 이 측정이 v0.5에서 **5칸 함선을 폐지한 직접적 근거**가 됐다. 사전 없이는 게임이 시작조차 안 되므로 0단계에서는 초성 일치만 보고 통과시킨다. 사전은 §6.4 파이프라인으로 따로 빌드해 나중에 끼우는 독립 부품이다.

UI의 `스텁 사전 (엄격)` 옵션은 **엄격 경로가 동작하는지 보기 위한 것**이고, 선택하면 자동 배치가 실패하는 게 정상이다.

## 랜덤 봇 대국 통계 (허용 사전, 10판) **[v0.9 보드]**

```
상륙 9 / 전멸 0 / 미결착 1 · 평균 116초
최단 상륙: 12회 이동 / 107초 (한 척만 집중해 밀었을 때)
```

보드 축소(250 → 160칸, 깊이 24 → 19)로 구 평균 173초에서 절반 가까이 줄었다.

두 가지가 보인다.

1. **"개빠른 상륙"은 규칙상 불가능하다.** 이동 쿨 9초 + AP 3(=7.5초치 수입)이 하한을 만든다.
2. **전멸 승리가 0건이다.** 랜덤 봇이 전투를 못한다는 점을 감안해도, 승리 경로 하나가 작동하지 않을 가능성이 있다. 밸런스 단계의 1번 관측 대상.

### 봇을 고치며 알게 된 것

첫 봇은 **15분 동안 한 척도 자기 진영을 벗어나지 못했다.** 이동이 3 AP인데 나머지가 더 싸서, 탐욕적으로 굴리면 싼 행동들이 AP를 계속 빨아가 이동에 필요한 3을 영영 못 모은다. 이동분을 먼저 떼어 두도록 고치자 바로 전진했다.

이건 봇 버그였지만 **실시간 전환이 만든 실제 플레이 포인트**이기도 하다. 턴제에서는 AP가 매 턴 초기화돼 안 쓰면 손해였는데, 이제는 **아끼는 것이 전략**이다.
